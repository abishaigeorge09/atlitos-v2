## Corrected: the gen-tokens typecheck failure was NOT a false alarm

An earlier note here claimed the node:fs/node:path errors were a race with
concurrent pnpm installs. That was wrong, and the P3 integrator disproved it.
apps/mobile declares TypeScript ~6.0.3 while the monorepo is on 5.x, so
`pnpm run typecheck` resolves 6.0.3 and fails DETERMINISTICALLY, whereas a bare
`npx tsc` resolves the hoisted 5.9.3 and passes. The two commands were running
different compilers. Fixed with types: ["node"] in 8b114c6; the version skew
itself is still there and is real debt. Lesson: when two ways of running the
same check disagree, find out which binary each resolved before calling either
one a flake.

## Limit and resume mechanics

Limits reset on a rolling window; the error always names the reset time. There
is no quota API, so nothing can poll for it, and an agent that tried would burn
the budget it was watching. The working pattern is:

1. On a limit error, read the reset time from the error text.
2. Update this file's Current position so a cold session loses nothing.
3. `claude-schedule ~/dev/atlitos HH:MM` (a few minutes after reset).
4. launchd fires `claude-resume`, which runs `claude -p` with the PROMPT above.

Observed resets this build: 16:00, 22:20, 01:00 IST, consistent with a rolling
5 hour window that starts on first use after a gap. Two projects running
concurrently share one quota, which is why it drains faster than expected.
